Bot API

Бот в Shalter — обычный аккаунт, которым управляет программа. Он состоит в чатах, пишет сообщения, показывает кнопки. Программу можно держать где угодно и писать на чём угодно — или прямо в приложении, без хостинга вообще.

Два способа сделать бота

Свой сервер, свой язык

Скрипт на вашей машине спрашивает у Shalter новые сообщения и отвечает на них. Нужен только исходящий интернет — ни белого IP, ни домена, ни вебхуков. Любой язык, любые библиотеки, своя база данных. Это и есть HTTP API ниже.

Редактор внутри Shalter

Функция на JavaScript, которая исполняется на сервере при каждом входящем сообщении. Ни токена, ни хостинга, ни цикла опроса. Быстрее всего для небольшого бота — и заметно ограниченнее, о чём честно сказано в разделе про ограничения.

Токен

Настройки → Боты → «Создать бота». У бота сразу появляется собственный аккаунт с юзернеймом вида @name_bot и токен — длинная строка, которая и есть право говорить от его имени. Токен виден там же, рядом с ботом; его можно перевыпустить, если он утёк.

Токен — это пароль бота. Кто им владеет, тот и есть бот: читает его чаты и пишет от его имени. Не кладите его в публичный репозиторий и не вставляйте в код фронтенда — только в переменные окружения на своей стороне.

Быстрый старт

Проверить, что токен рабочий, — одна команда:

curl -H "Authorization: Bearer ВАШ_ТОКЕН" \
  https://shalter.ru/api/bot-api/me

В ответ придёт аккаунт бота. Дальше — рабочий бот целиком, на голом Node без единой зависимости:

const TOKEN = process.env.SHALTER_TOKEN;
const API = "https://shalter.ru/api/bot-api";
const auth = { Authorization: `Bearer ${TOKEN}`, "Content-Type": "application/json" };

let after = new Date().toISOString(); // начинаем с «сейчас», старое не разгребаем

async function send(chatId, text) {
  await fetch(`${API}/sendMessage`, {
    method: "POST",
    headers: auth,
    body: JSON.stringify({ chatId, text }),
  });
}

async function tick() {
  const res = await fetch(`${API}/updates?after=${encodeURIComponent(after)}`, { headers: auth });
  const { messages } = await res.json();
  for (const msg of messages) {
    after = msg.createdAt; // следующий опрос — строго после последнего разобранного
    if (msg.text === "/start") await send(msg.chatId, "Привет! Я бот.");
    else await send(msg.chatId, `Вы написали: ${msg.text}`);
  }
}

setInterval(() => tick().catch(console.error), 2000);

Авторизация

Все запросы к /api/bot-api/* требуют заголовка: 

Authorization: Bearer ВАШ_ТОКЕН

Без него — 401 с текстом Missing Authorization: Bearer <token>, с неверным — 401 Invalid bot token. Куки и сессии здесь не используются: бот не человек, он не «входит» в приложение.

Кто я

GET /api/bot-api/me

Возвращает аккаунт бота — имя, юзернейм, аватар. Нужен, чтобы проверить токен и узнать свой id.

{ "bot": { "id": "u_17…", "name": "Погодный", "username": "pogodnyy_bot", "isBot": true } }

Новые сообщения

GET /api/bot-api/updates?after=<ISO-время>

Отдаёт сообщения из чатов бота, пришедшие после указанного времени. Свои собственные сообщения бот в ответе не увидит — иначе он отвечал бы сам себе по кругу.

ПараметрТипОписание
afterстрока, ISO 8601Время последнего разобранного сообщения. Без него отдаётся всё с начала времён.

Сообщения отсортированы по возрастанию времени, поэтому следующее значение after — это messages.at(-1).createdAt. За один запрос отдаётся не больше 200 сообщений: разговорчивый бот не должен получить в ответ всю свою историю.

Опрос, а не вебхук — намеренно. Вебхук требует публичного адреса и сертификата; опрос работает откуда угодно, включая ноутбук за NAT. Раз в 1–2 секунды более чем достаточно.

Отправка

POST /api/bot-api/sendMessage
ПолеТипОписание
chatIdстрокаОбязательное. Куда писать — берётся из msg.chatId входящего сообщения.
textстрокаОбязательное. Пустой текст отклоняется с 400.
replyToIdстрокаОтветить на конкретное сообщение — в чате будет видна цитата.
keyboardмассив рядовКнопки под сообщением, см. ниже.

Бот может писать только в те чаты, где он состоит: попытка написать в чужой чат вернёт 404 Bot is not a member of this chat. Это не формальность — иначе токен любого бота превращался бы в право рассылки по всему мессенджеру.

Картинки и файлы

POST /api/bot-api/sendPhoto
POST /api/bot-api/sendDocument

Вложение передаётся ссылкой, а не загрузкой файла: у бота уже есть где хранить свои картинки, а второй путь загрузки на сервер тянул бы за собой свои лимиты, чистку и квоты. Годится и data:-URL, если файл маленький и генерируется на лету.

ПолеТипОписание
chatIdстрокаОбязательное.
urlстрокаОбязательное. Адрес картинки или файла.
captionстрокаПодпись — она же становится текстом сообщения.
nameстрокаТолько для sendDocument: имя файла, которое увидит человек.
replyToIdстрокаОтветить на сообщение.
 
await fetch(`${API}/sendPhoto`, {
  method: "POST", headers: auth,
  body: JSON.stringify({ chatId, url: "https://example.com/chart.png", caption: "Отчёт за неделю" }),
});

Правка и удаление

POST /api/bot-api/editMessageText
POST /api/bot-api/deleteMessage

Первый принимает messageId и новый text, второй — только messageId. Изменения видны всем в чате сразу, без перезагрузки.

Бот может править и удалять только свои сообщения — чужое вернёт 403. Это не формальность: токен бота живёт на чьём-то сервере, и право стирать чужие слова там ему не нужно. 

const { message } = await (await fetch(`${API}/sendMessage`, {
  method: "POST", headers: auth, body: JSON.stringify({ chatId, text: "Считаю…" }),
})).json();

const result = await heavyWork();

await fetch(`${API}/editMessageText`, {
  method: "POST", headers: auth,
  body: JSON.stringify({ messageId: message.id, text: `Готово: ${result}` }),
});

Закрепление

POST /api/bot-api/pinChatMessage

Принимает messageId и pinned (true по умолчанию, false — открепить). Здесь правило другое, чем у правки: закрепить можно и чужое сообщение, но только там, где бот администратор. Закреп видит весь чат — это действие модератора, а не отправителя. В личном чате с ботом ограничения нет.

Печатает…

POST /api/bot-api/sendChatAction

Принимает chatId. Показывает в чате, что бот думает над ответом — то, что отличает занятого бота от зависшего. Живёт пять секунд, как и у людей: перед длинным шагом повторяйте, а не ставьте один раз в начале.

Чаты и люди

GET /api/bot-api/getChats

Все чаты, где состоит бот: id, тип, название, число участников и признак админа. Без него единственный способ узнать свой чат — дождаться, пока туда кто-нибудь напишет.

GET /api/bot-api/getChat?chatId=…

Один чат подробно, вместе со списком участников.

GET /api/bot-api/getUser?userId=…

Кто написал. В сообщении приходит только senderId; отсюда берутся имя и юзернейм, чтобы ответить «Спасибо, Аня», а не «Спасибо, u_1786…». Чужой адрес почты не отдаётся никогда — ни здесь, ни где-либо ещё.

Кнопки

keyboard — массив рядов, каждый ряд — массив кнопок. Нажатие отправляет боту обычное сообщение с текстом из data, так что обрабатывается оно там же, где и всё остальное. 

await fetch(`${API}/sendMessage`, {
  method: "POST",
  headers: auth,
  body: JSON.stringify({
    chatId,
    text: "Что показать?",
    keyboard: [
      [{ text: "Погода", data: "/погода" }, { text: "Курс", data: "/курс" }],
      [{ text: "Помощь", data: "/help" }],
    ],
  }),
});

Команды

Список команд задаётся в приложении (Настройки → Боты → иконка списка) в формате BotFather — по одной на строку: 

start - Начать
погода - Прогноз на сегодня
help - Что я умею

Он показывается людям по кнопке «/» в чате с ботом. Сами команды приходят обычными сообщениями с текстом /погода — отдельного типа события для них нет.

GET /api/bot-api/getMyCommands
POST /api/bot-api/setMyCommands

То же самое из программы — удобно обновлять список вместе с выкладкой новой версии бота, а не руками. Ведущий слэш можно не писать, он всё равно срезается. 

await fetch(`${API}/setMyCommands`, {
  method: "POST", headers: auth,
  body: JSON.stringify({ commands: [
    { command: "start", description: "Начать" },
    { command: "погода", description: "Прогноз на сегодня" },
  ]}),
});

Редактор внутри приложения

Настройки → Боты → иконка кода. Внутри — настоящий редактор (подсветка синтаксиса, автодополнение по Bot API, парные скобки, поиск, отмена), кнопка «Запустить» для проверки на тестовом сообщении и консоль с логами вашего бота.

Код исполняется на сервере, при каждом входящем сообщении. Токен, хостинг и цикл опроса не нужны вовсе.

handleMessage

Единственное требование к коду — определить эту функцию:

async function handleMessage(msg, bot) {
  if (msg.text === "/start") {
    return bot.send("Привет! Напишите что-нибудь.");
  }

  // Можно ходить в чужие API прямо отсюда
  const res = await fetch("https://api.example.com/weather?city=Moscow");
  const data = await res.json();

  await bot.send(`Сейчас ${data.temp}°`, {
    keyboard: [[{ text: "Обновить", data: "/погода" }]],
  });
}
Что доступноОписание
msgВходящее сообщение: id, chatId, senderId, text, createdAt.
bot.send(text, opts)Ответить в тот же чат. opts — те же keyboard и replyToId.
bot.sendTo(chatId, text, opts)Написать в другой чат, где бот состоит.
fetchОбычный fetch — запросы к внешним сервисам.
console.log / warn / errorПишет в консоль редактора и в журнал бота.
setTimeout / clearTimeoutЗадержки внутри обработчика.

Ограничения — читать до того, как писать

Поверхность намеренно узкая: require, process, файловая система, модули npm и глобальные объекты Node недоступны.

  • Состояние не сохраняется. Каждый вызов начинается с чистого листа: переменные не переживают следующее сообщение. Нужна память — храните её во внешнем сервисе через fetch, или пишите бота на своём сервере.
  • 300 мс непрерывной работы процессора. Ожидание (fetch, отправка) сюда не считается — у него свой потолок в 20 секунд на весь вызов. Ограничение жёсткое по неприятной причине: сервер однопоточный, и пока ваш синхронный код крутится, приложение не отвечает никому.
  • 20 секунд на вызов целиком. Медленный внешний API успеет ответить, зависший — нет.
Песочница — не защита от чужого кода. В документации Node про модуль vm сказано прямо: это не средство безопасности. Здесь он ограничивает случайный ущерб от вашего собственного кода — опечатки, бесконечного цикла, забытого await. Не вставляйте туда скрипт от незнакомца: это ровно то же самое, что запустить у себя чужой шелл-скрипт.

Писать в VS Code

Встроенный редактор — это редактор одного файла, а не среда разработки: без дерева проекта, отладчика, npm-пакетов, git и расширений. Если нужно всё это — пишите бота у себя в VS Code как обычную программу и подключайте его по HTTP API из первой половины страницы. Тогда доступно ровно всё, к чему вы привыкли: любые зависимости, точки останова, тесты, своя база, деплой куда угодно.

Разница только в том, где живёт программа. Формат сообщений и отправка одинаковые: bot.send() в редакторе и POST /sendMessage снаружи — это один и тот же вызов внутри.

Ошибки

КодКогда
400Пустой text в sendMessage.
401Нет заголовка Authorization или токен недействителен.
404Бот не состоит в этом чате либо чат не существует.
429Слишком часто. Опрос раз в 1–2 секунды в лимиты укладывается с запасом.

Ошибка внутри кода в редакторе не роняет ни сервер, ни бота: она попадает в журнал бота (Настройки → Боты → код → консоль), а следующее сообщение обрабатывается как ни в чём не бывало.
