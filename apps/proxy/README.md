# Прокси Shalter

Как прокси MTProto у Telegram, только для Shalter: любой может поднять его на своём сервере
и раздать ссылкой или QR-кодом. Тот, у кого основной адрес Shalter заблокирован, открывает
ссылку прокси — и весь сайт (страницы, API, файлы, WebSocket) идёт через этот сервер.

- Без зависимостей: только Node 22.18+ (`node src/main.ts`, типы Node снимает сам).
- Сервер Shalter ничего настраивать не должен: прокси подставляет его Host, Origin и Referer,
  а адрес клиента передаёт в `X-Forwarded-For`.
- Cookie сессии ставятся на адрес прокси (без `Domain`, `Secure` — только по https).
- Перенаправления на файлы в S3 (`302` из `/uploads/…`) прокси проходит сам и отдаёт клиенту
  содержимое: хранилище из такой сети может быть так же недоступно, как сайт.
- С `PROXY_SECRET` прокси отвечает только тем, кто хоть раз открыл ссылку с секретом
  (дальше — cookie); всем остальным — обычный `404`, так что найти его перебором адресов нельзя.

## Ссылка

`https://<адрес прокси>/?proxy=<PROXY_SECRET>` (без секрета — просто `https://<адрес прокси>/`).
Её можно открыть в браузере — сайт загрузится через прокси. В Shalter: «Настройки → Прокси»
сохраняет ссылки, подключается и показывает QR-код; страница, открытая через прокси, сама
показывает «Вы подключены через прокси» и QR, чтобы поделиться дальше.

## Запуск

Сборка образа (из корня репозитория или из скопированной папки `apps/proxy`):

```sh
docker build -t shalter-proxy apps/proxy
```

Без своего домена, по IP (http):

```sh
docker run -d --name shalter-proxy --restart unless-stopped -p 80:8080 \
  -e PROXY_SECRET="$(openssl rand -hex 12)" shalter-proxy
docker logs shalter-proxy   # здесь ссылка для друзей
```

По http браузер не даёт сайту микрофон, камеру, уведомления и офлайн-режим — звонки и
голосовые не заработают. Для них нужен HTTPS: домен (подойдёт и бесплатный, например на
duckdns.org) и Caddy, который сам получит сертификат:

```sh
cd apps/proxy
PROXY_DOMAIN=proxy.example.net PROXY_SECRET="$(openssl rand -hex 12)" docker compose up -d --build
```

Без Docker: `SHALTER_UPSTREAM=https://shalter.ru PORT=8080 node src/main.ts`.

## Переменные окружения

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `SHALTER_UPSTREAM` | `https://shalter.ru` | Сервер Shalter, к которому идут запросы |
| `PROXY_SECRET` | — | Секрет ссылки (8–128 символов `A–Z a–z 0–9 - _`). Без него прокси открыт всем |
| `PORT` / `HOST` | `8080` (`443` с TLS) / `0.0.0.0` | Где слушать |
| `TLS_CERT_FILE`, `TLS_KEY_FILE` | — | Свой сертификат: прокси сам слушает https |
| `PROXY_TRUST_FORWARDED` | — | `1`, если перед прокси свой фронт (Caddy, nginx): адрес и схема клиента — из `X-Forwarded-For`/`-Proto` |
| `PROXY_PUBLIC_URL` | — | Публичный адрес прокси для ссылки «Поделиться» (иначе — из `Host` запроса) |
| `PROXY_RELAY_HOSTS` | `storage.yandexcloud.net,*.storage.yandexcloud.net` | Хосты хранилища, на чьи перенаправления прокси идёт сам |

## Ограничения

- Прокси видит весь трафик между клиентом и сервером (как любой HTTPS-обратный прокси):
  пользуйтесь прокси тех, кому доверяете.
- Ключи доступа (passkeys) привязаны к домену Shalter и через прокси не работают — входите паролем или кодом.
- Ссылки, которые сервер строит сам (вход по QR, приглашение в звонок), ведут на основной адрес.
- С `PROXY_SECRET` манифест PWA браузер запрашивает без cookie, поэтому «установить как приложение»
  через закрытый прокси не получится; сам сайт работает.
- Все, кто ходит через прокси, для сервера приходят с одного адреса: лимит попыток входа
  (`AUTH_RATE_LIMIT`, на адрес) у них общий, пока сервер не доверяет этому прокси
  (`SHALTER_TRUSTED_PROXIES` на сервере, DEPLOY.md).

## Тесты

`npm test -w @shalter/proxy` — поддельный сервер Shalter (node:http + ws): страницы, тело потоком,
cookie, Range, перенаправления и файлы из «S3», WebSocket, вход по секрету.
