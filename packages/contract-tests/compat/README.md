# Совместимость данных

Главная страховка переезда на NestJS: новый сервер обязан открыть **существующую**
базу `data/app.db` и зашифрованные файлы `data/uploads/` и отдать всё байт-в-байт.

- `fixture/` — каталог `data/`, записанный текущим (Express) сервером через публичный API:
  3 пользователя, личка, группа, канал с постом (и его обсуждение), секретный чат;
  юникод/эмодзи, текст на 4000 символов, ответы, правки, реакции, опрос, голосовое
  с расшифровкой; файлы png (с превью, которое сделал сервер), txt (сжат brotli,
  загружен дважды — дедупликация), 300 КБ .bin (сжат, много чанков), 200 КБ .zip
  (не сжат, отдаётся по Range). Писалось с `KEY_ROTATION_SECONDS=10` и паузами —
  в базе несколько ключей сообщений и файлов (`crypto_keys`). Без `outbox/`.
- `fixture.manifest.json` — всё, что нужно читателю: пароли и device_id пользователей,
  id чатов и сообщений с ожидаемыми текстами, файлы с sha256, полный снимок того,
  что каждый видит через API, номера ключей. Мастер-ключи — `TEST_KEYS` из `support/env.ts`.
- `read-fixture.test.ts` — поднимает сервер на копии фикстуры и сверяет всё с манифестом,
  дописывает новое в старую базу и проверяет, что всё переживает перезапуск.
- `schema.test.ts` — схема фикстуры совпадает со схемой свежей базы текущего сервера;
  на диске нет открытого текста. Единственное место, где тесты открывают SQLite напрямую.

## Пересобрать фикстуру

Нужно, только если формат хранения меняется **намеренно** (новая миграция в
`server/db.js` — тогда `schema.test.ts` упадёт). Генерировать — текущим (legacy)
сервером, никогда не новой реализацией: фикстура — эталон старого формата.

```
BUILD_COMPAT_FIXTURE=1 npx vitest run --config packages/contract-tests/vitest.config.ts compat/build-fixture
```

Занимает ~25 секунд (ждёт две ротации ключей). Перезаписывает `fixture/` и манифест —
id и шифротекст каждый раз новые, коммитить вместе.
