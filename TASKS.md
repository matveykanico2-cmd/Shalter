# Задачи Shalter

Последнее обновление: 2026-11-15. Новые продуктовые задачи выполняются по этапам и не должны ломать текущие контракты NestJS/React.

## Этап 1 — надёжность интерфейса

- [ ] Проверить главное меню «три полоски» и каждую его кнопку на телефоне, в браузере и в нативных оболочках; починить неработающие действия.
- [ ] Проверить остальные основные кнопки приложения e2e-сценариями, начиная со списка чатов, профиля и настроек.
- [ ] Убрать лишние перезагрузки: внутренние переходы выполнять через React Router, а данные обновлять через Query/WS. Полную перезагрузку оставлять только там, где требуется изоляция аккаунтов или новая версия клиента.
- [x] «Добавить аккаунт» открывает экран входа внутри SPA и не закрывает приложение. После успешного входа состояние прежнего аккаунта очищается полной загрузкой намеренно.
- [x] Нажатие на аватар с цветным фоном и буквами открывает полноэкранный просмотр, в том числе на главном экране настроек.
- [x] Короткая загрузка lazy-экранов больше не мигает: индикатор появляется только при ожидании дольше 160 мс.

## Этап 2 — ссылки, файлы и медиа

- [x] При открытии внешней ссылки или переходе показывать понятное короткое уведомление «Ссылка открыта», не создавая повторных переходов.
- [x] После сохранения файла сообщать, что файл сохранён, и предлагать открыть/посмотреть его; если формат поддерживается — просмотреть внутри Shalter.
- [x] Не скачивать один и тот же файл повторно для просмотра: использовать уже сохранённую копию, когда оболочка даёт к ней безопасный доступ.
- [x] Скачанные из чатов файлы запоминаются в разделе «Загрузки» и повторно открываются оттуда.
- [x] Нативное Android-приложение сообщает путь сохранённого файла; iOS показывает системное меню сохранения/открытия.
- [x] У видеокружка до запуска показывается обложка или первый кадр вместо чёрного круга.

## Этап 3 — обновления приложения

- [x] Клиент узнаёт версию установленной Android/iOS/desktop-оболочки, сравнивает её с доступной сборкой и предлагает обновиться, если установленная версия старее.
- [ ] Добавить серверное понятие минимально поддерживаемой версии для обязательного обновления, отдельно от обычного предложения новой версии.
- [ ] Проверить обновление старых оболочек, которые ещё не передавали номер версии, и сценарии без сети/через прокси.
- [x] Для Linux оставлена одна распространяемая сборка `.deb`; AppImage и RPM убраны из страницы, API и процесса сборки.

- [x] Если пользователь запретил входящие звонки, предлагать звонящему создать и отправить ссылку-приглашение вместо одной ошибки.
- [x] Добавить контрактные тесты на продажу/закрепление/передачу юзернейма и на звонок по ссылке при запрете входящих.

## Этап 6 — уведомления, сообщества и отправка

- [x] Не присылать push о новом сообщении из чата, который сейчас открыт и видим на этом устройстве; в фоне, после выхода из приложения и в другом чате push остаётся.
- [x] Управлять участниками чатов сообщества из профиля сообщества: единый список, поиск по имени/юзернейму/телефону и кнопка добавления.
- [x] При добавлении в сообщество добавлять человека во все его чаты и отправлять в каждом служебное сообщение; для чатов сообщества убрать отдельное добавление участников.
- [x] Добавить настройку прав сообщества: добавлять участников могут все либо только администраторы; в подробностях связанного чата показывать кликабельное название сообщества.
- [x] Медиа и подпись отправлять одним сообщением и одной кнопкой; незавершённые загрузки продолжать в фоне, не блокируя следующую отправку.
- [x] Исправить отправленные карточки контактов: получатель может открыть профиль, добавить контакт и начать чат, в том числе если карточку прислал Shalter AI.

- [x] Увеличенные лимиты Shalter AI для Premium отображаются из того же серверного тарифного объекта, который применяет квоты.

## Этап 8 — регрессии сообщений, историй и звонков

- [x] Закрывать модальные overlay завершённым кликом, чтобы тап не срабатывал на кнопке под уже размонтированным полупрозрачным окном.
- [x] В цитате ответа на стикер показывать миниатюру исходного стикера, а не один смайл или слово «Стикер».
- [x] В списке поставивших реакцию показывать все аккаунты с аватарами и открывать профиль по нажатию.
- [x] Обычная ссылка на неотвеченный входящий звонок больше не принимает вызов; ответ остаётся только явным действием пользователя.
- [x] В обсуждениях и комментариях свои ответы центрировать; у поста канала разнести просмотры, время и стрелку комментариев.
- [x] После добавления человека в контакты из его профиля сразу открывать имя, фамилию, заметку, своё фото/смайл и предложение фото.
- [x] Для новой двухэтапной защиты показывать только облачный пароль; старые TOTP/чат-коды пока поддерживать для входа и безопасного отключения существующих аккаунтов.
- [x] Автоудаление сообщений по сроку доступно в подробностях личек и управляемых групп/каналов и выполняется фоновым sweep.
- [x] Подавлять повторный `message:new` с тем же chat/message id до звука, push и обработчиков; добавить тест повторной доставки (серверные события с разными id не теряются).
- [x] Убрать рывок и краткую остановку при догрузке старых сообщений, сохраняя якорь виртуализированной ленты.
- [x] Изолировать внутренние чаты сообщества от общего списка, фильтров, поиска, архива и счётчиков; агрегировать новые сообщения только на карточке сообщества.
- [x] Завершить профиль сообщества: участники, поиск, добавление и единые права без отдельного управления в связанных чатах.
- [x] Добавить настройку канала «отправлять от имени аккаунта / канала» и сохранять выбранную личность автора в обычной, платной, Bot API и отложенной публикации.
- [x] Ускорить первое открытие тем, каналов, групп и профиля сообщества; безопасную карточку предзагружать отдельно от отмечающей прочтение истории, детали сообщества и членство загружать параллельно.
- [ ] Проверить полный сценарий звонка на двух реальных устройствах: разрешения, offer/answer, ICE restart, плохая сеть и завершение.

## Уже существующие ограничения

- Изменения поведения API сопровождаются схемами `packages/shared` и контрактными тестами.
- Продакшен выкладывается только после резервной копии и зелёных проверок по инструкции `DEPLOY.md`.
- Шифрование сообщений и файлов остаётся byte-compatible с текущими данными.
