# Задачи Shalter

Последнее обновление: 2026-11-14. Новые продуктовые задачи выполняются по этапам и не должны ломать текущие контракты NestJS/React.

## Этап 1 — надёжность интерфейса

- [ ] Проверить главное меню «три полоски» и каждую его кнопку на телефоне, в браузере и в нативных оболочках; починить неработающие действия.
- [ ] Проверить остальные основные кнопки приложения e2e-сценариями, начиная со списка чатов, профиля и настроек.
- [ ] Убрать лишние перезагрузки: внутренние переходы выполнять через React Router, а данные обновлять через Query/WS. Полную перезагрузку оставлять только там, где требуется изоляция аккаунтов или новая версия клиента.
- [x] «Добавить аккаунт» открывает экран входа внутри SPA и не закрывает приложение. После успешного входа состояние прежнего аккаунта очищается полной загрузкой намеренно.
- [x] Нажатие на аватар с цветным фоном и буквами открывает полноэкранный просмотр, в том числе на главном экране настроек.
- [x] Короткая загрузка lazy-экранов больше не мигает: индикатор появляется только при ожидании дольше 160 мс.

## Этап 1.1 — единый дизайн в стиле Telegram

- [ ] Привести список чатов, шапки и главное меню к одной сетке размеров, отступов и состояний нажатия.
- [x] Первый проход чата: плавающая стеклянная шапка, скруглённое полотно, закреплённая плашка, сообщения, поле отправки и диалоги на телефоне и компьютере.
- [ ] Привести профили, настройки, звонки и диалоги к общей системе карточек, анимаций и адаптивных переходов.
- [ ] Проверить светлую и тёмную темы, узкие экраны, клавиатуру телефона и режим уменьшения движения.
- [x] Праздничная плашка показывает дату и праздник и открывает существующую отправку подарка без новой вкладки.

## Этап 2 — ссылки, файлы и медиа

- [ ] При открытии внешней ссылки или переходе показывать понятное короткое уведомление «Ссылка открыта», не создавая повторных переходов.
- [ ] После сохранения файла сообщать, что файл сохранён, и предлагать открыть/посмотреть его; если формат поддерживается — просмотреть внутри Shalter.
- [ ] Не скачивать один и тот же файл повторно для просмотра: использовать уже сохранённую копию, когда оболочка даёт к ней безопасный доступ.
- [x] Скачанные из чатов файлы запоминаются в разделе «Загрузки» и повторно открываются оттуда.
- [x] Нативное Android-приложение сообщает путь сохранённого файла; iOS показывает системное меню сохранения/открытия.
- [x] У видеокружка до запуска показывается обложка или первый кадр вместо чёрного круга.

## Этап 3 — обновления приложения

- [x] Клиент узнаёт версию установленной Android/iOS/desktop-оболочки, сравнивает её с доступной сборкой и предлагает обновиться, если установленная версия старее.
- [ ] Добавить серверное понятие минимально поддерживаемой версии для обязательного обновления, отдельно от обычного предложения новой версии.
- [ ] Проверить обновление старых оболочек, которые ещё не передавали номер версии, и сценарии без сети/через прокси.
- [x] Для Linux оставлена одна распространяемая сборка `.deb`; AppImage и RPM убраны из страницы, API и процесса сборки.

## Этап 4 — аккаунты, юзернеймы и звонки

- [ ] После продажи юзернейма назначать продавцу временный сгенерированный юзернейм и предлагать заменить его своим; явно предупреждать, что старый юзернейм не возвращается.
- [ ] Купленный юзернейм закреплять за аккаунтом покупателя и не запрещать перенос на другой свой аккаунт при замене и можно отдать другу его или что то дргое тоесть механника как в телеграмм аккаунт в обход предусмотренной продажи.
- [ ] Если пользователь запретил входящие звонки, предлагать звонящему отправить ссылку-приглашение вместо одной ошибки.
- [ ] Добавить контрактные тесты на продажу/закрепление юзернейма и на предложение ссылки при запрете звонков.

## Этап 5 — Shalter AI

- [ ] Улучшить качество ответов помощника и работу со сложными заданиями.
- [ ] Научить помощника создавать презентации и другие готовые файлы.
- [ ] После создания файла явно сообщать, что он прикреплён и его можно скачать или посмотреть в приложении.

## Уже существующие ограничения

- Изменения поведения API сопровождаются схемами `packages/shared` и контрактными тестами.
- Продакшен выкладывается только после резервной копии и зелёных проверок по инструкции `DEPLOY.md`.
- Шифрование сообщений и файлов остаётся byte-compatible с текущими данными.
